Functional Specification Deep Dive

REQUIREMENT CARD 002
FR-002 CORE AI INFERENCE SLA: <180ms

AI Deload & Fatigue Modulation Engine

Functional Intent

The engine processes historical weight-velocity decay over the previous 14 sessions combined with the user's Apple Health overnight HRV and resting heart rate. If negative velocity variance exceeds 12% across 3 consecutive sessions in compound lifts, the engine automatically prescribes an active deload protocol.

Acceptance Criteria (Gherkin Verification) 3 / 3 PASSING IN TEST RIG
check_circle
Scenario 1: Acute Fatigue Overload Trigger

Given user logs RPE ≥ 9.5 for compound movements 2 sessions in a row,
And morning HRV is >15% below baseline for 48h,
When the user initiates a new hypertrophy block,
Then inject a 'Deload Prompt' reducing target volume by 40% while preserving working intensity.

check_circle
Scenario 2: User Override Grace Period

Given an active deload recommendation card appears on screen,
When user taps 'Override & Keep Heavy Weight',
Then append an telemetry anomaly tag #USER_OVERRIDE_FATIGUE and request confirmation for sets exceeding 90% 1RM.

check_circle
Scenario 3: Offline Local Inference Fallback

Given zero cellular or Wi-Fi connectivity in the gym basement,
When workout completes,
Then calculate fatigue score via quantized local CoreML model and queue server cloud sync with priority batch ID.

error Edge Case: Corrupted Biometric Stream

If Apple Health records gaps > 72 hours, suppress auto-adjustment and fallback strictly to manual RPE entries without prompting false alarms.

speed Latency Budget Constraint

On-device ML pipeline must resolve within 45ms to avoid UI stutter when navigating between workout tabs.
